## 二、改了什么

### 1. 配置面（`src/host.mjs` + `src/client.mjs`）
- `Config`：`dockEnabled` → `paneEnabled`，并给 `paneEnabled`/`position`/`recentHidden`/`recentCollapsible` 各补 `.description()`（宿主配置面板与插件页卡片的提示文案来源）。
- `PANE_OPTION_DEFAULTS.paneEnabled = true`；`effectivePaneOption` **显式** `key === "paneEnabled"` 分支（既有布尔兜底落到 `recentCollapsible` 的键，漏加会读错项）。
- **存储键串沿用旧值 `dsh-activity-pane:dock-enabled`**（改名会让升级用户的选择丢失并留下孤儿键）。

### 2. 停用后两列都不出现（`src/client.mjs`）
- `ensurePane()` 首行：`if (paneOptions.paneEnabled === false) return null;`——左右都不建窗格。
- 新增 `releasePaneForDisabled()`：摘 `[data-dsh-activity-pane]`、`releaseDetachedPaneBinding(true)`、清 `renderedPane`/`lastSig`/`lastOptionSig`/`pulseSignature`、`toggle.remove()`、`backdrop.removeAttribute("data-drawer-open")`、`applyLayout(true)`。
- `applyLayout(forceRelease)` 新增首参：停用时要还原插件写进宿主外壳的中间列内联样式（`flexDirection`、`alignItems`、会话座的 `flex`/`minWidth`），否则中央区会留一列空地。
- `placeToggle()` 首行停用早退（先 `toggle.remove()` 再 return）。
- `render()` 在 `rightTabNeedsRequest` 消费块之后、`ensurePane` 之前插停用收口（先 `releaseRightDockWiring()` + `sweepRightDockTabs()`，见 §2b），并照常跑 `deriveActiveModel()` + `syncBadgeSurface()` + `renderBadgeModal()`。

### 2b. 停用时右栏入口一并注销（东家 2026-11-12 追加，m01990）
- 需求原话：「关闭 启用活动会话窗格, 右侧侧边栏也不再注册入口」——停用后宿主右栏的**本插件 tab 与引导页入口都不能留**。
- **推翻了 C-110 决策 8**：当年判断「宿主 `sidebarRightTabs` 没有运行期注销 API」是错的。真实实现（`.tmp-asar/out2/dsh/node_modules/@deepseek-ai/dsh-client-ui-sidebar-right/lib/client.js:4905-4933`）里 `register()` 的返回值就是幂等 disposer：`const dispose = this.ctx.effect(() => { ids.add; enter(); refresh(); return () => { ids.delete; leave(); refresh(); }; }); return () => { dispose(); };`。tab 条（`:5662-5665` `tabTypes.getSnapshot → tabs.entries()`）与引导页（`:5728-5731` `tabs.guide()`）读同一张表 → 注销即等于两处入口同时消失。详见 `RATIONALE/C-111-pane-disable-unregisters-right-dock.md`。
- **只注销类型不够**：无注册类型的 tab 是宿主承认的状态（`:1620-1632` 渲染 `<p data-sidebar-right-unavailable>` + 「这类内容还没有可用的查看方式」），会留一个空壳。所以必须先关已开的 tab，再注销类型。
- 新增三个函数（`src/client.mjs`，`connectSidebarRight` 之后）：
  - `closeRightDockTabs()`：遍历**全部会话**（`sidebar.tabsIn(id)`，不只当前屏），关掉 `kind === RIGHT_TAB_KIND` 的 tab；有 `closeIn` 用它（对所有已采纳 store 的会话有效），否则退回 `close`（只作用于屏上会话）。
  - `sweepRightDockTabs()`：宿主把 tab 布局存在 `localStorage["dsh.sidebar-right.v1.<sessionId>"]` 且**不校验 kind 是否注册**，停用期切会话时旧 tab 会复活 → 按「在屏会话变了」重开三轮清扫窗口。
  - `releaseRightDockWiring()`：先 `closeRightDockTabs()` → 摘 `rightSlotDisposer`（正文/标题席位）→ 注销 `rightTabDisposer` → `sidebarRightHost = null; paneWiringAttempted = false;`（复位后重新启用能自动重注册并重开 tab）。
- `render()` 停用分支顺序：`releaseRightDockWiring()` → `sweepRightDockTabs()` → `releasePaneForDisabled()`（先关 tab 再撤窗格，撤完不再回头找 tab）。重新生效的补接线块里把 `rightDockSweptFor`/`rightDockSweepRounds` 归零。
- 设置卡片与 `Config.description` 文案同步：「…宿主右侧栏的本插件 tab 与引导页入口一并撤除；宿主侧栏角标与 Ctrl+Tab 快捷切换保留。」

### 4. 快捷切换显式确认（`src/quick-switch.mjs`）

### 5. 当前行置顶 + 工作区标签

### 5c. 失焦语义（东家 2026-11-12：失焦后要么忽略快捷键、要么关闭窗口）
- 两条收口通道：`window` 的 `blur`（切应用/最小化/宿主切走）与 `document` 捕获期 `pointerdown`（点浮层外任意区域，命中面板与遮罩时 return）。
- `pointerdown` **不** `preventDefault`/`stopPropagation`：用户点的按钮该响还得响，浮层只顺手收起。不用 `click`——等它落地时宿主默认动作已排队。
- `onQuickSwitchKeyDown` 首行：`if (!document.hasFocus())` → 若浮层还在屏则补一次收起，然后 `return`（失焦期间不接管任何热键）。
- **刻意不挂 `visibilitychange`**：切标签页/最小化都会先触发 `blur`，两者覆盖同一场景；漏拍由 `hasFocus()` 兜底。东家 2026-11-12 明确「多余的失焦监听移除」。
- 每条监听都要成对：`open`/`close`/`dispose` 三处。

### 5d. 两档确认：短按松开即跳、长按再按一次（东家 2026-11-12 追加，m01643）
- 背景：上一版一律「松开不跳、再按 Ctrl 才确认」。东家要的是——按住 Ctrl 超过 2s 才沿用旧口径；不足 2s 的快速 Ctrl+Tab 松开就跳。
- 常量：`QUICK_SWITCH_TAP_MS = 2000`（改这一处即可调整分档阈值）。
- 打点位置很关键：基准是 **`Control` 自己的 `keydown`**（`quickSwitchCtrlDownAt`），不是 Ctrl+Tab 那一刻——用户可能先按住 Ctrl 停一会儿再按 Tab。必须判 `!event.repeat`，否则按住不放的自动重复会把基准一路刷新成 0 秒。
- 分档只在**唤出那一次 Ctrl 的 keyup** 上生效：不足 2s → 直接 `commitQuickSwitch()`；超过 2s → 置 `quickSwitchConfirmArmed` 并留在屏上等第二次 Ctrl（此后任何一次 Ctrl 松开都提交，不再看时长）。
- `onQuickSwitchKeyUp` 把结算（清打点、清定时器）提到 `quickSwitchOpen` 判空**之前**：浮层没开时按的那一下 Ctrl 也要清，留着会让下一次 Ctrl+Tab 拿旧时刻算时长、永远落进 hold 档。
- 提示条联动：Ctrl 那一格文案是变量（`QUICK_SWITCH_HINT_TAP_LABEL` / `QUICK_SWITCH_HINT_HOLD_LABEL`），`syncQuickSwitchHintMode()` 按「此刻松开会不会跳」判断（而不是「按了多久」）——待命态下只要按着就显示「松开即跳」，不会出现「写着再按确认、松手却跳了」的错标。
- 长按不动时没有按键事件可依赖，`armQuickSwitchTapTimer()` 起一次性 `setTimeout` 在跨阈值那一刻补刷；**关灯、Ctrl 松开、卸载三处都必须 `clearQuickSwitchTapTimer()`**，否则 2s 后会戳已经移出文档的 DOM。
### 5e. 浮层模态遮罩（东家 2026-11-12 追加，m02369）
- 需求原话：「quick Switch 弹窗时增加遮罩层」；追问后明确两点：① 点遮罩**收起浮层，且不触发背后的页面**；② 「大小和点击左侧的活动会话弹窗宽度一样，且居中位置也一样」、「和点击角标的遮罩一样」。
- `.dap-qs-veil` 从「退场专用浅暗」改成常驻模态遮罩：`color-mix(in srgb, var(--dsw-alias-bg-mask-2, #0b0d12) 78%, transparent)` + `backdrop-filter: blur(3px)`，与角标明细弹窗的 `.dap-modal-backdrop` 逐字同档。
- **遮罩在屏期间（含退场那 260ms）保留指针命中**：这才是「不触发背后页面」的实现方式——不用逐个宿主控件去判断浮层是否开着，也不用 `preventDefault`（会吞掉用户本意的点击）。`onQuickSwitchPointerDown` 因此删掉了「遮罩内 return」分支。
- 面板尺寸与位置同样对齐 `.dap-modal`：`width: min(600px, 100vw - 48px)`、`max-height: min(76vh, 640px)`、`left/top: 50%` + `translate(-50%, -50%)`，`top: 14vh` 已废弃。**关键帧必须同步改成 `translate(-50%, -50%)`**——否则入场动画的 `transform` 会把面板从「双向居中」覆盖成「只有水平居中」，视觉上跳到视口下方。
- 显形顺序：`veil.hidden = false` **先**，再 `veil.removeAttribute("data-closing")`。反过来的话上一轮退场的 `forwards` 动画会把 opacity 按在 0，看起来像遮罩没出来。
- 收尾：遮罩不另起定时器，与面板共用 `QUICK_SWITCH_CLOSE_MS = 260`；两层各自计时会留一帧「只有遮罩」的暗屏。
- 面板补 `aria-modal="true"`（遮罩确实挡住了背后内容，语义要如实）。

## 四、已知陷阱（后续维护必读，本轮新增第 5-9 条）

1. **折叠早退不能提交 `lastSig`/`lastOptionSig`**（T-191 已有，仍然成立）。
2. **`connectSidebarRight` 的两道守卫都不能省**：`paneEnabled === false` 早退 + `rightTabDisposer !== null` 幂等返回。
3. **重新启用时先落盘再补接线**（判据读同一条三级回退链）。
4. **右栏正文 cleanup 必须带 `data-dap-docked="right"` 守卫**。
5. **停用收口必须在 `ensurePane` 之前**。放在之后会先建一帧窗格再撤，肉眼可见闪动。
6. **插件设置卡片不能跟着 `paneEnabled` 一起门控**。它是停用态唯一能把窗格开回来的入口；跟着一起跳过就变成「关掉后再也打不开」。
7. **`subscribe`/`getSnapshot` 必须稳定引用**。在组件体内新建闭包 → `useSyncExternalStore` 报 "The result of getSnapshot should be cached" 并无限重渲染。
8. ~~**停用时不注销 `rightTabDisposer`/`rightSlotDisposer`**。宿主 `sidebarRightTabs` 只给 `register`；强行调 disposer 会让 tab 类型从宿主表消失而插件侧留悬空引用，重新启用无法再注册。~~ **本条已由 C-111 推翻（2026-11-12）**：`register()` 返回的就是幂等 disposer。正确做法见第 10-12 条。
10. **注销右栏入口必须「先关 tab、再摘席位、最后注销类型」**。顺序反了会先出现一帧「无可用查看方式」的空壳；只注销不关 tab 则空壳永久留下。
11. **两名 disposer 要先本地取引用再置空**（`const disposeSlot = rightSlotDisposer; rightSlotDisposer = null; try { disposeSlot(); } catch {}`）。直接调再置空，一旦 disposer 抛错就留下永远非 null 的守卫，重新启用再也注册不上。
12. **tab 记录的字段是 `id` 不是 `tabId`**（宿主 `:1255-1260` 的 `{ id, kind, contentId, title }`）。按 `tab.tabId` 读永远是 `undefined`，会让「关 tab」静默跳过。
13. **不注销的那部分**：`PANE_SETTINGS_SLOT` 的卡片、宿主侧栏角标、Ctrl+Tab 浮层——三者在停用态都要照常工作，别跟着一起撤。
