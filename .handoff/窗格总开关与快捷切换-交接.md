## 二、改了什么

### 1. 配置面（`src/host.mjs` + `src/client.mjs`）
- `Config`：`dockEnabled` → `paneEnabled`，并给 `paneEnabled`/`position`/`recentHidden`/`recentCollapsible` 各补 `.description()`（宿主配置面板与插件页卡片的提示文案来源）。
- `PANE_OPTION_DEFAULTS.paneEnabled = true`；`effectivePaneOption` **显式** `key === "paneEnabled"` 分支（既有布尔兜底落到 `recentCollapsible` 的键，漏加会读错项）。
- **存储键串沿用旧值 `dsh-activity-pane:dock-enabled`**（改名会让升级用户的选择丢失并留下孤儿键）。

### 2. 停用后两列都不出现（`src/client.mjs`）
- `ensurePane()` 首行：`if (paneOptions.paneEnabled === false) return null;`——左右都不建窗格。
- 新增 `releasePaneForDisabled()`：摘 `[data-dsh-activity-pane]`、`releaseDetachedPaneBinding(true)`、清 `renderedPane`/`lastSig`/`lastOptionSig`/`pulseSignature`、`toggle.remove()`、`backdrop.removeAttribute("data-drawer-open")`、`applyLayout(true)`。
- `applyLayout(forceRelease)` 新增首参：停用时要还原插件写进宿主外壳的中间列内联样式（`flexDirection`、`alignItems`、会话座的 `flex`/`minWidth`），否则中央区会留一列空地。
- `placeToggle()` 首行停用早退（先 `toggle.remove()` 再 return）。
- `render()` 在 `rightTabNeedsRequest` 消费块之后、`ensurePane` 之前插停用收口，并照常跑 `deriveActiveModel()` + `syncBadgeSurface()` + `renderBadgeModal()`。

### 3. 插件设置卡片（新增，停用态唯一入口）
- 宿主**没有** schema→表单渲染器（`dsh-client-ui-plugin-manager/lib/client.js:6019-6023` 只 `renderSlot("plugins.bundle.config", { view: "page" }, { entryKey: pkg.name })`），所以插件自带 React 组件。
- `PANE_SETTINGS_SLOT = "plugins.bundle.config"`，key = 包名 `dsh-activity-pane`；`createPaneSettingsCard(react, controller, subscribe, getSnapshot)` 用 `useSyncExternalStore` 读、`controller.set("paneEnabled", !enabled)` 写；`view === "summary"` 返回 null。
- `subscribe`/`getSnapshot` 在 `connectPaneSettingsSlot()` 里**一次建好**（稳定引用，否则 `useSyncExternalStore` 无限重渲染——宿主 pwsh7 卡片踩过同一坑）。
- 装配段：`paneWiringAttempted = true`；`rightReact()`/`connectSidebarRight()` 仍按 `paneEnabled` 门控；`connectPaneSettingsSlot()` **无条件**调用。

### 4. 快捷切换显式确认（`src/quick-switch.mjs`）
- 新增 `let quickSwitchConfirmArmed = false;`；`openQuickSwitch()`/`closeQuickSwitch()` 都重置。
- `onQuickSwitchKeyUp`：仅 Control；未置位时按**按住时长**分档（不足 `QUICK_SWITCH_TAP_MS` 直接提交，否则只置位）；已置位才 `commitQuickSwitch()`。详见 §5d。
- `onQuickSwitchKeyDown`：浮层内 Tab/Shift+Tab/↑↓ → `cycle`；Enter → `commit`；Esc → `cancel`；已打开时 Ctrl+Tab 只 `cycle` 不提交。

### 5. 当前行置顶 + 工作区标签
- `publishQuickSwitchCandidates(entries, currentId, currentTitle, currentWorkspace)` 增第 4 参；当前行 `workspace`/`workspaceKey` 取自它。
- `model` 顺序：当前会话组 → running → waiting → done（文档序置顶）。
- `renderQuickSwitch` 里 `quickSwitchOrder = [...order, ...cancelOrder]`（循环序当前行在末尾，首按 Tab 不浪费在取消项上）。
- `client.mjs` 的 `publish` 调用补第 4 实参 `workspaceInfoForSession(...)`。
- 「当前」标签（东家 2026-11-12：「当前没有搞成标签」）：原来是行尾 10px 灰底小胶囊（深色主题下看不见），现改为标题行**最前**的圆角胶囊，`line.append(here, ws, title)`——扫读序「当前 → 工作区 → 标题」。

### 5c. 失焦语义（东家 2026-11-12：失焦后要么忽略快捷键、要么关闭窗口）
- 两条收口通道：`window` 的 `blur`（切应用/最小化/宿主切走）与 `document` 捕获期 `pointerdown`（点浮层外任意区域，命中面板与遮罩时 return）。
- `pointerdown` **不** `preventDefault`/`stopPropagation`：用户点的按钮该响还得响，浮层只顺手收起。不用 `click`——等它落地时宿主默认动作已排队。
- `onQuickSwitchKeyDown` 首行：`if (!document.hasFocus())` → 若浮层还在屏则补一次收起，然后 `return`（失焦期间不接管任何热键）。
- **刻意不挂 `visibilitychange`**：切标签页/最小化都会先触发 `blur`，两者覆盖同一场景；漏拍由 `hasFocus()` 兜底。东家 2026-11-12 明确「多余的失焦监听移除」。
- 每条监听都要成对：`open`/`close`/`dispose` 三处。

### 5b. 浮层底部快捷键提示条（东家 2026-11-12 追加，m01365）
- `QUICK_SWITCH_HINTS` 常量表（唤出 / 切换、移动、Ctrl 确认口径、确认、取消）驱动 `createQuickSwitchFooter()`；键帽是 `kbd.dap-qs-key`，标签 `span.dap-qs-hint-label`。Ctrl 那一格带 `mode: "ctrl"`，文案随档位切换（见 §5d）。
- `menu.append(body, footer)`；footer `flex: none` + `border-top`，正文滚动时不动；整条 `pointer-events: none`，不参与 Tab 循环序列。
- 样式定位：字号比正文小一档（footer 10px、键帽 9px），`justify-content: flex-end` 整条靠右，整条 `opacity: .72`；键帽**无底色无描边**——东家 2026-11-12 两次追加「小一点、靠右」→「还是有点太突出，弱化一点」。
- **改键位必须同时改两张表**：`QUICK_SWITCH_HINTS`（显示）与 `onQuickSwitchKeyDown`/`onQuickSwitchKeyUp`（行为）。`scripts/check.mjs` 对两者都有硬断言，漏改一边 check 会红。
- 与 C-108 的关系：当年删的是「一行散文说明」（读一次就够），本次恢复的是「键位表」（显式确认语义下不可猜）；已写进 C-110 决策 11。

### 5d. 两档确认：短按松开即跳、长按再按一次（东家 2026-11-12 追加，m01643）
- 背景：上一版一律「松开不跳、再按 Ctrl 才确认」。东家要的是——按住 Ctrl 超过 2s 才沿用旧口径；不足 2s 的快速 Ctrl+Tab 松开就跳。
- 常量：`QUICK_SWITCH_TAP_MS = 2000`（改这一处即可调整分档阈值）。
- 打点位置很关键：基准是 **`Control` 自己的 `keydown`**（`quickSwitchCtrlDownAt`），不是 Ctrl+Tab 那一刻——用户可能先按住 Ctrl 停一会儿再按 Tab。必须判 `!event.repeat`，否则按住不放的自动重复会把基准一路刷新成 0 秒。
- 分档只在**唤出那一次 Ctrl 的 keyup** 上生效：不足 2s → 直接 `commitQuickSwitch()`；超过 2s → 置 `quickSwitchConfirmArmed` 并留在屏上等第二次 Ctrl（此后任何一次 Ctrl 松开都提交，不再看时长）。
- `onQuickSwitchKeyUp` 把结算（清打点、清定时器）提到 `quickSwitchOpen` 判空**之前**：浮层没开时按的那一下 Ctrl 也要清，留着会让下一次 Ctrl+Tab 拿旧时刻算时长、永远落进 hold 档。
- 提示条联动：Ctrl 那一格文案是变量（`QUICK_SWITCH_HINT_TAP_LABEL` / `QUICK_SWITCH_HINT_HOLD_LABEL`），`syncQuickSwitchHintMode()` 按「此刻松开会不会跳」判断（而不是「按了多久」）——待命态下只要按着就显示「松开即跳」，不会出现「写着再按确认、松手却跳了」的错标。
- 长按不动时没有按键事件可依赖，`armQuickSwitchTapTimer()` 起一次性 `setTimeout` 在跨阈值那一刻补刷；**关灯、Ctrl 松开、卸载三处都必须 `clearQuickSwitchTapTimer()`**，否则 2s 后会戳已经移出文档的 DOM。

## 四、已知陷阱（后续维护必读，本轮新增第 5-9 条）

1. **折叠早退不能提交 `lastSig`/`lastOptionSig`**（T-191 已有，仍然成立）。
2. **`connectSidebarRight` 的两道守卫都不能省**：`paneEnabled === false` 早退 + `rightTabDisposer !== null` 幂等返回。
3. **重新启用时先落盘再补接线**（判据读同一条三级回退链）。
4. **右栏正文 cleanup 必须带 `data-dap-docked="right"` 守卫**。
5. **停用收口必须在 `ensurePane` 之前**。放在之后会先建一帧窗格再撤，肉眼可见闪动。
6. **插件设置卡片不能跟着 `paneEnabled` 一起门控**。它是停用态唯一能把窗格开回来的入口；跟着一起跳过就变成「关掉后再也打不开」。
7. **`subscribe`/`getSnapshot` 必须稳定引用**。在组件体内新建闭包 → `useSyncExternalStore` 报 "The result of getSnapshot should be cached" 并无限重渲染。
8. **停用时不注销 `rightTabDisposer`/`rightSlotDisposer`**。宿主 `sidebarRightTabs` 只给 `register`；强行调 disposer 会让 tab 类型从宿主表消失而插件侧留悬空引用，重新启用无法再注册。
9. **`Config` schema 的默认值不是原型里的值**。实测 schemastery 3.18.4：`schema({})` 给缺失键填的是带 `get`/`Symbol(cosmokit.volatile.write)` 的访问器对象（`JSON.stringify` 出来是 `{}`），不是 `true`/`'left'` 字面量。所以 `syncHostConfigValue()` 拿到的 `hostConfigValue.paneEnabled` 未必是布尔——`effectivePaneOption` 的 `typeof raw === "boolean"` 守卫与卡片里 `typeof snap.value.paneEnabled === "boolean"` 的兜底都是必需的，不要简化成直接取用。
