# C-104 本 fork 的验证改为全手动，不挂任何自动门禁

日期: 2026-10-19

#### 上下文
- 实测事实：本机从未设置 hooksPath，Git 自带钩子目录只有示例文件，因此仓库内那套提交/推送校验脚本一次都没被执行过——「提交/推送自动门禁」实际并不存在。
- 与此同时，可手动执行的几层检查在本机全线故障：
  - 测试影响检查器调用 git 时未指定输出编码，Windows 下按 GBK 解码含中文的内容抛解码错误，随后把空值当成文档正文解析而崩溃；自检与正式检查双双失败退出。
  - AgentMap 校验器把三份运行时文件钉在固定哈希上，其中两份因 CRLF 转换在工作区必然失配，检出之后校验必红。
  - 同一校验器的自检在 Windows 上因写临时文件未指定编码而编码失败。
- 后果：快速验证实测 50.2 秒（文档称「约 5 秒」），且永远在文档校验处短路，浏览器 E2E 一次都跑不到；要确认行为只能逐个用例手跑，全量实测 7.8–26 分钟。「改一次跑很多遍」由此而来。
- 东家明确要求：自动门禁与强制测试全部改为手动，只有需要时才测。

#### 决策
1. 移除全部自动门禁：不安装 Git 钩子，CI 只保留手动触发，推送不再触发任何检查。
2. 文档口径同步：项目规矩里的权威验证入口登记为「手动」；项目说明增设「验证策略：全手动」一节，删除「每次工作完成都要跑完整验证」「必须验证后再报完成」一类强制表述。
3. 门禁相关检查从硬错误降级为告警：AgentMap 校验器不再因钩子缺席、注册表不一致、扫描来源缺失而失败，也不再要求权威验证入口必须指向可执行文件。
4. 修掉让手动验证本身不可用的硬故障：两处输出编码问题，以及浏览器 E2E 的桌面端启动器探测（本机只装了新版渠道，默认值指向不存在的旧渠道；且新版把命令行入口打进归档包，按普通文件存在性判断恒为假）。
5. 基线既有失败显式登记：包清单新增已知失败用例列表，E2E 运行器对清单内用例失败时记为已知失败，不让整轮跑红。

#### 被否方案及原因
- 保留钩子但改薄：钩子从未安装过，改薄解决不了「看起来有门禁、实际没有」的误导；东家要的是「我需要测试时才测试」。
- 只改文档不改脚本：文档说手动、脚本仍因编码问题必红，手动验证照样跑不起来。
- 删除校验脚本与工具层：这些脚本仍是有价值的检查能力（追溯检查、测试影响分析），保留并声明「不启用」成本更低。
- 把已知失败用例直接跳过：会让覆盖静默消失；已知失败仍照常执行并留存失败取证，只是不参与本轮判红。

#### 影响面
维护者流程（本 fork 无对应 task；改动集中在包清单、E2E 运行器与启动器、两份校验器、项目规矩与项目说明、CI 配置、以及单元检查里的一条 CI 触发契约）
