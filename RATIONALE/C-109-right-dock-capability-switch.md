# C-109 右栏停靠改为能力级开关：装配期即跳过接线，而不是「少渲染一档」

日期: 2026-11-11

#### 上下文
东家 2026-11-11 提问三连：「右侧边栏打开活动会话，对整体性能是否有影响」「可否单独关闭右侧边栏」「关闭后不影响左侧活动会话」。基于代码的结论是：窗格停靠在宿主右栏时，卡片 DOM 写入与逐卡 `getBoundingClientRect` 全部落在右栏正文里；用户点 tab 上的 X 关掉它只能省掉这部分——tab 类型与正文/标题席位仍注册在宿主的注册表里，宿主每次重排右侧栏都要过一遍本插件的贡献，且本插件是右栏唯一的停靠 tab，还会触发宿主「唯一停靠 tab 关闭即整列收起」的规则。东家据此授权「彻底停掉右侧栏成本、保留左侧角标」。

三条硬约束：一是角标（R-01-026）与窗格共享每轮派生，但角标不依赖窗格挂载，停用右栏不得削弱它；二是本 fork 持续合并上游，改动应新增而非改写；三是验证策略全手动。

#### 决策
1. **能力级开关而非呈现档**：新增配置项 `dockEnabled`（缺省 `true`，`.volatile()`），停用时在装配期就跳过右侧栏接线——`rightReact()` 与 `connectSidebarRight()` 都不执行，连 `require("react")` 都不发生。只做「少渲染一档」仍会留下 tab 注册与席位注入的常驻成本，与东家「彻底停掉」的口径不符。
2. **生效值走既有三级回退链**（宿主配置通道 → localStorage → 缺省），与其余三项呈现配置同一条路径。`effectivePaneOption` 必须为 `dockEnabled` 显式加分支：既有的布尔分支兜底到 `recentCollapsible` 的键，漏加会读到错误的存储项。
3. **停靠判定统一收口**：`syncPaneDock` 与 `ensurePane` 的「是否去右栏」都改成 `paneOptions.dockEnabled !== false && paneOptions.position === "right" && desktopQuery.matches`。停用只影响停靠判定，不动 `position` 的值——重新启用后窗格立刻回到右栏。
4. **位置控件同步退场**：停用时标题行的位置切换按钮 `hidden`，设置弹层里的「面板停靠到右侧」整行 `hidden`。留着可点但点了没效果的开关比不给更糟。两处都需显式补 `[hidden]` 规则——`.dap-dock` 与 `.dap-settings-row` 都是 `display: flex`，会盖掉 UA 的 `[hidden]`。
5. **运行期可逆**：复选框变更时先写双通道再补接线，顺序不可颠倒——`connectSidebarRight` 的启用判据读的是同一条回退链，反过来会读到旧的 `false` 而直接早退。函数自身加「已注册即返回」的幂等守卫，重复调用不会让宿主右栏出现两个同 id 的 tab 类型。
6. **运行期无法注销已注册的 tab 类型**（宿主 `sidebarRightTabs` 只提供 `register`，disposer 要等插件整体卸载才生效），故运行期停用的落点是「不再请求打开、不再挂正文、窗格退回左列」，那个空置的 tab 留到下次启动才消失。启动即停用则完全没有这个过程。这条限制写进 PRD 的 AC-02，不假装能做到运行期注销。
7. **折叠态与右栏互斥**：`syncPaneDock` 切到右栏时复位 `collapsed`。左列折叠后切右栏，若不复位，`data-collapsed="true"` 会让右栏正文只剩 34px 窄条，而右栏态的标题行已摘掉 role/tabindex（R-01-021 的右栏分支），用户既看不全也点不开——是把人卡死的死角。
8. **顺带收口两处既有缺陷**：① `bindPaneControls` 在 document 上挂 capture 监听，唯一的解绑入口是「换了新窗格」分支与卸载段；右栏 tab 被关闭时 `ensurePane` 在 `:4610` 早退、不解绑，绑定成为没人解绑的常驻监听。新增 `releaseDetachedPaneBinding(force)` 统一三条路径（早退前、换面时、卸载时）。② 折叠窄条只靠 CSS `display:none` 收起滚动区，卡片仍被逐张写入并测量，量到的全是 0；折叠态整段跳过卡片写入、只同步数量标识，`syncTracks` 再加一道零高度早退。折叠早退**刻意不提交渲染签名**——本轮没把卡片 DOM 更新到当前数据，记成「已渲染」会让展开时被同签名短路、停在旧内容。

#### 被否方案及原因
- 复用 `position=left` 当「关闭右栏」：那是搬家，面板仍在屏、仍全量渲染，右栏接线成本一分不少。
- 只让右栏正文不渲染（保留 tab 注册与席位注入）：tab 注册仍在宿主注册表里，宿主重排右栏仍要过一遍贡献，且仍会触发「唯一停靠 tab」规则——与「彻底停掉」的名义不符。
- 运行期调 disposer 注销 tab 类型：宿主只给 `register`，`disposer` 只在插件卸载时生效；强行调用会让 tab 类型从宿主的表里消失而插件的 `rightTabDisposer` 变成悬空引用，下一次启用无法重新注册。
- 停用时把 `position` 一并改写为 `left`：会把用户的停靠偏好写坏，重新启用后无法恢复原位置。
- 折叠态与右栏并存（折叠窄条也挂到右栏正文）：右栏宽度与开合由宿主接管，34px 窄条在右栏里既无意义又点不开。

#### 影响面
R-01-029 / 右栏停靠开关（新需求条目）、宿主配置 `Config`（新增 `dockEnabled`，与 `PANE_OPTION_DEFAULTS` 的缺省值必须一致）、窗格渲染器（停靠判定、设置弹层、折叠早退、绑定回收、轨道测量早退）、新增 e2e 规格 `right-dock-toggle`。角标子系统（R-01-026）的数据通路与呈现均不变。
