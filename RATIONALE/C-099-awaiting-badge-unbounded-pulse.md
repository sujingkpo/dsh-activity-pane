# C-099 「需要交互」角标用无界常闪，与「瞬时过程不得无界」的纪律划界

日期: 2026-10-15

#### 上下文
东家需求（2026-10-15）：「如果是存在 `需要交互` 动画需要一直闪，直到处理完成」。当时该角标只有一次性强调——计数增加时播 `dap-badge-hit-alert`（0.8s × 4）后由定时器摘属性收口，仍未处理的交互随后重新静默下去。

本仓库对无界动画有明确纪律：R-01-005/AC-01 的「打开中」提示曾因无界闪烁被否决，门禁至今断言该提示为限次动画且不得含 `infinite`，其理由记为「无界闪烁的直接成因」。因此「一直闪」不能照字面直接落地，必须先划清与既有禁令的边界。

#### 决策
按动画承担的**状态语义**划界，而非按动画形式划界：瞬时过程（正在尝试打开、正在迁移）不得无界——无界即意味着该过程永不结束，是故障信号；持续状态（存在待你处理的交互、存在阻塞等待）无界正是要求——动画的终止条件就是状态的解除。

据此为侧栏角标的「需要交互」引入常闪：计数 > 0 期间挂 `data-badge-awaiting`，走 `dap-badge-await-pulse`（1.6s ease-in-out infinite）+ 复用 `dap-badge-halo` 的外扩环；计数归零即摘。该选择与仓库既有的 `dap-await-pulse`（等待胶囊，1.2s infinite，三处）同属「持续状态用无界」一侧，形成一致口径。属性按计数**声明式**给出而非命令式挂摘，使其随宿主重渲染与 React 重挂自动跟随；与一次性新增强调的关系交给 CSS 级联（常闪规则在前、一次性在后且权重更高）而非 JS 互斥。`prefers-reduced-motion` 下只关动效、保留金色状态色。

#### 被否方案及原因
- 照字面给现有一次性强调加 `infinite`：一次性强调的语义是「刚刚新增」，把一次事件变成永久动画会让「新」的含义消失，且它由定时器收口、与无界自相矛盾。
- 让常闪也走 JS 定时器续挂：需要自己记账与清理，且在宿主重渲染/组件重挂时会连同属性一起丢；声明式由 React 与 CSS 各自负责其擅长的一半，成本更低。
- 用 `data-badge-hit` 复用同一属性承载常闪：一次性强调的收口逻辑（摘 `data-badge-hit`）会把常闪一并摘掉；两个状态各有生命周期，必须各占一个属性。
- 常闪期间用 JS 摘掉一次性强调以免两者同现：两者同现时后者本就应当优先（刚新增比持续存在更值得注意），且 CSS 级联已能正确表达，加互斥只是重复机制。
- 为常闪同时改 `dap-opening` 的限次断言：把「瞬时过程」与「持续状态」的区别一并抹掉，等于放弃这条纪律；本次只新增，不动既有断言。
